## 0. 前置修正（M0.6 验收遗留）
- **限流可配置**：e2e 批量注册会耗尽"每 IP 每分钟 60 次"的鉴权限流，M0.6 靠每轮重启 API 绕过，不可接受。把 IP / 账号两个限流额度做成环境变量（`AUTH_RATE_LIMIT_IP_PER_MINUTE` 默认 60、`AUTH_RATE_LIMIT_ACCOUNT_PER_MINUTE` 默认 20），生产默认值不变；`docker-compose.dev.yml` 或 worker 的 `.env` 为开发/e2e 调高（如 6000）。`make e2e` 连续运行无需重启任何服务。
- **日期时间中文格式**：修改记录显示为 "11/7/2026, 10:02:38 AM"。所有日期时间格式化统一走 `src/domain/format.ts`（`Intl.DateTimeFormat(zh-CN, …)`，如"11月7日 10:02"、跨年加年份），全局搜索替换 `toLocaleString()` 等无 locale 调用；加单测。
- **按钮与提示风格统一**：截图中"行程提示（1）"、"知道了"、提示条"查看"是纯黑底按钮，不属于设计令牌。统一使用 Button 变体：主操作 primary、次要 secondary/outline、提示条 action 用 primary。"行程提示"改为页面顶栏中的图标按钮 + 数字徽标，数量为 0 时不显示徽标（不再占整行）。
- **提示条不遮挡弹层**：有弹层（Drawer/Dialog）打开时，Sonner 提示条改到顶部居中显示（或上移到弹层之上），截图中提示条盖住了弹层底部内容。
- 行程条目列表的视觉（左对齐卡片、时间列）在本任务第 4 节一并重做，不再是居中表格行样式。

## 1. 数据（后端实体注册表 + 前端类型，schemaVersion 仍为 1：只新增可选字段与新实体，旧 op 兼容）
### itinerary_item（在 M0 基础上扩展）
| 字段 | 类型 / 校验 |
|---|---|
| title | 必填，1–200 |
| date | 必填，YYYY-MM-DD（开始日期） |
| startTime / endTime | 可空，`HH:MM` 24 小时制 |
| timezone | 可空，IANA；为空表示使用行程默认时区 |
| endDate | 可空，YYYY-MM-DD，≥ date（跨夜 / 跨时区航班到达日） |
| endTimezone | 可空，IANA；为空表示与 timezone 相同 |
| place | 可空，≤200 |
| bookingInfo | 可空，≤2000，自由文本 |
| voucherIds | 可空，UUID 字符串数组，≤20 项（M4 使用，本任务只做字段校验与透传） |
| wishItemId | 可空，UUID |
| sortOrder | 可空，分数索引字符串（≤64，仅 `[0-9A-Za-z]`），用于无时间条目的手动排序 |
### wish_item（新实体，任何当前成员可 create/update/delete/restore）
| 字段 | 类型 / 校验 |
|---|---|
| title | 必填，1–200 |
| note | 可空，≤2000 |
| url | 可空，≤2000，必须是 http/https 绝对地址（服务端校验） |
| place | 可空，≤200 |

**D14（写入 decisions.md）：心愿"已安排"状态由数据推导，不存 scheduledItemId。** 心愿已安排 ⇔ 存在未删除的 itinerary_item 其 wishItemId = 该心愿 id。理由：离线并发下"心愿上的指针"与"行程项"两处数据会不一致；推导则在删除、恢复、撤销、冲突时天然正确。两人离线同时安排同一心愿会产生两个行程项，都显示，心愿显示最早的那天，并在心愿上提示"已安排 2 次"。spec 第 3 节数据模型中 WishItem 的 scheduledItemId 相应改为说明"由行程项推导"。

## 2. 排序（前端 domain 纯函数 + 单测）
- 每天条目：**无时间条目在前**（视为全天/待定，按 sortOrder，再按 createdSeq），**有时间条目在后**按 startTime 升序（同时间按 sortOrder、createdSeq）。
- 手动排序使用分数索引（引入成熟库 `fractional-indexing`）：只改被移动条目的 sortOrder，不重排其它条目。
- 跨夜条目（endDate > date）只在开始日显示，并标注"→ 次日 08:30"或"→ 11月12日 08:30（当地）"。
- 时间显示：当地时间 + 时区缩写（条目时区与行程默认时区不同时才显示时区，如"14:05 JST → 18:30 CET"）。

## 3. 心愿池（features/wishlist）
- 入口：行程 tab 顶部"心愿池（N 未安排）"卡片/按钮，进入心愿池页面（也可从"更多"之外直接到达，路由 `/trips/:id/wishes`）。
- 列表：**未安排**的在顶部，已安排的在下方并显示"已安排（第 N 天）"，点击跳转到对应行程项。
- 新增 / 编辑 / 删除（软删除 + 撤销提示条）：ResponsiveOverlay 表单（标题、备注、链接、地点）。链接在卡片上可点击（`target=_blank rel=noopener noreferrer`）。
- **"安排到…"按钮（主路径）**：打开日期选择（行程每一天的列表"第 N 天 · 11月10日 周二"），选择后生成 itinerary_item（title/place 取自心愿，wishItemId=心愿 id，date=所选日，sortOrder 排到当天无时间条目末尾），提示条附"撤销"（删除该行程项）。
- **拖拽（桌面/平板 ≥ 840px）**：行程页使用双栏布局，左侧当天列表、右侧心愿池；用 dnd-kit 把心愿拖到某天即安排；也支持在同一天内拖拽调整无时间条目的顺序、跨天拖拽改日期。触摸设备支持长按拖拽，但手机布局不显示双栏，仍以按钮为主。
- 已安排心愿的行程项上提供"移回心愿池"：软删除该行程项（提示条可撤销），心愿自动回到未安排。

## 4. 行程表（扩展 M0.6 的列表）
- 每天分组标题"第 N 天 · 11月10日 周二"，今天高亮并在进入页面时自动滚动到今天（行程进行中时）。
- 条目卡片：时间（或"未定时间"）、标题、地点、预订信息摘要（第一行）、来自心愿的标记。
- 编辑表单字段：标题、日期、开始/结束时间（手机原生 `input type=time`，桌面同样用原生 time，日期桌面使用 shadcn Calendar 弹层）、时区（默认行程时区，"更多选项"中可改出发/到达时区与到达日期）、地点、预订信息（多行）。表单内显示"修改记录"入口（M0.6 已有）。
- 无时间条目在手机上提供"上移 / 下移"操作（菜单中），桌面支持拖拽。
- "移到其它天"：菜单操作，选择日期。
- 行程日期范围外的条目保留 M0.6 的"未在行程日期内"分组。
- 预订信息中的电话号码、网址自动识别为可点击链接（简单正则，纯文本渲染，防 XSS）。

## 5. 修改记录
- wish_item 与扩展后的 itinerary_item 字段均有中文字段名映射（标题、日期、开始时间、结束时间、时区、到达日期、到达时区、地点、预订信息、心愿、排序 等）；排序字段的变更在记录中显示为"调整了顺序"，不显示索引字符串。

## 6. 测试
- 后端：新字段与 wish_item 的校验集成测试（非法时间、非法时区、endDate < date、非 http 链接、voucherIds 非 UUID、sortOrder 非法字符）。
- 前端单测：排序函数（含跨夜、同时间、无时间混排）、分数索引插入、"已安排"推导（含已删除行程项、两次安排）、时间与时区显示格式化。
- Playwright（手机视口为主）：
  1. 新增心愿 → "安排到…"第 2 天 → 心愿显示"已安排（第 2 天）"、行程表第 2 天出现该项 → 撤销 → 心愿回到未安排。
  2. 安排后在行程项上"移回心愿池" → 心愿未安排；在修改记录中可见创建与删除。
  3. 离线安排心愿、编辑时间与预订信息 → 恢复网络后另一成员看到一致结果。
  4. 无时间条目上移/下移后，另一成员看到相同顺序。
  5. 桌面视口：把心愿拖到某天（dnd-kit，使用 Playwright 的鼠标拖拽）安排成功。
  6. 两成员离线同时安排同一心愿 → 恢复后两边都显示两项，心愿提示"已安排 2 次"。
