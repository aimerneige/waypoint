# 任务 M0.6：ItineraryItem 最小列表 + 冲突 / 拒绝 / 修改记录界面 + 退出清理 + M0 端到端验收

前置：M0.1–M0.5 已完成。先阅读 `docs/sync-protocol.md`、`spec.md` 第 2.3、2.5、2.6、2.7、6.1 节、`docs/decisions.md` D12，以及现有 `web/src/{domain,data,sync,ui,features}`。

## 1. 行程 tab：ItineraryItem 最小实现（D12）
- 字段：title（必填，≤200）、date（必填，限制在行程日期范围内，手机原生 date input）、place（可空，≤200）。
- 按行程日期生成"第 N 天 · M月D日 周X"分组，每组列出当天条目（本任务按创建顺序即可，排序规则 M1 再做）；行程日期范围外的条目放"未在行程日期内"分组。
- 右下角 Fab 新增；点条目打开 ResponsiveOverlay 编辑；删除走软删除，提示条附"撤销"（restore op）。
- 全部通过 M0.5 的统一写入入口，离线可用。

## 2. 冲突与删除提示（spec 2.3）
- 拉取到含 `conflicts` 的 op 时，若与当前用户有关则写入 `notices`：
  - 当前用户是本 op 的 actor：「你对"标题"的修改覆盖了 Y 的修改（旧值 → 新值）」。
  - 当前用户是 overwrittenActor：「你对"标题"的修改被 Y 覆盖（你的值 → Y 的值）」。
  每条提示提供"恢复为旧值"（生成新的 update op，恢复的是被覆盖的值）与"知道了"。
- 推送结果 `entityDeleted=true`：提示「该项已被 Y 删除」，提供"恢复该项"（restore op）。
- 展示方式：新提示弹出提示条（带"查看"）；行程页顶部有提示入口（徽标数），点击打开提示列表（ResponsiveOverlay）。同一 op 的提示不重复生成（幂等）。

## 3. 未生效的修改（spec 2.5）
- SyncStatus 为"有修改未生效"时可点击，打开列表：每条显示实体、操作、字段值与中文拒绝原因（按协议文档的拒绝码映射）。
- 操作：**修改后重试**（打开对应编辑表单，预填被拒内容，保存时生成新 opId 的新 op，baseSeq 基于当前 server 状态）、**丢弃**。
- 验证：本地 view 已回滚，不得把被拒内容显示为已生效。

## 4. 修改记录（spec 2.6）
- 条目编辑面板内"修改记录"：从本地 `ops` 表读取该实体的 op，显示 谁 / 何时（serverTime，本地时区格式化）/ 字段 / 旧值 → 新值，冲突的 op 标记"冲突"。离线可查看。
- "更多 → 修改记录"：行程级时间线（本地 ops 倒序、分页加载），含服务器生成的 trip/member op（显示为"X 加入了行程""X 把行程名改为…"等中文描述）。
- 首次同步走快照时本地 ops 表不完整：时间线底部提供"加载更早记录"（在线调用 history 接口补齐并存入本地）。

## 5. 退出登录与版本
- 退出登录：若该用户 outbox 非空，先提示"有 N 条修改尚未同步，退出将丢失"，确认后：删除该用户的 Dexie 数据库、Cache Storage 中的凭证缓存（M4 才有，先预留清理函数）、`wp:lastUser`，再调用 logout 接口（离线时也允许本地退出）。
- 实现 M0.4 留下的 `onBeforeLogout` 钩子。
- `upgrade_required` 时显示持续横幅"应用版本过旧，请刷新更新"，点击触发 PWA 更新。

## 6. M0 端到端验收（Playwright，必须）
在 `web/e2e/m0-sync.spec.ts` 中，以两个浏览器上下文（用户 A 为 owner、B 为成员，同一行程，手机视口）实现：
1. **离线各自修改后一致**：A、B 都在线并同步到同一条目 → 双方 `setOffline(true)` → A 改该条目 title、B 改同一条目 place、A 新增条目 X、B 新增条目 Y、B 删除另一条目 Z → 双方恢复在线 → 等待同步完成 → 断言两边列表完全一致（title 为 A 的值、place 为 B 的值、X/Y 都存在、Z 已删除）。
2. **冲突有提示**：A、B 离线后都改同一条目同一字段 → A 先上线同步，B 后上线 → B 收到"覆盖了 A 的修改"提示、A 收到"被 B 覆盖"提示（A 在线经 SSE 收到）→ A 点"恢复为旧值" → 双方最终都显示 A 的值，修改记录中可见三次修改。
3. **拒绝正确回滚**：B 离线编辑条目 title；B 的页面用 `page.route` 改写推送请求，把该 op 的 title 改成 201 个字符（服务器校验失败）→ B 上线 → 断言 B 的 view 回滚到旧值、"有修改未生效"出现且原因为中文；取消改写后点"修改后重试"改为合法值 → 成功同步，A 看到最终值。
4. **删除后编辑**：A 离线编辑条目，B 在线删除该条目 → A 上线 → A 收到"该项已被 B 删除"并可恢复 → 恢复后双方都可见。
5. **被移出行程**：B 离线有待同步修改时被 A 移出 → B 上线后收到提示、行程消失、本地该行程数据被清除。
6. **退出清理**：有未同步修改时退出登录出现 N 条提示，确认后 IndexedDB 中该用户数据库不存在。
以上用例必须稳定：禁止固定 sleep，使用"等待 SyncStatus 为已同步"等显式条件。
